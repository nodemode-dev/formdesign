# FormDesign harness

FormDesign is a professional page-layout application whose engine runs on the person's computer. Its MCP server lets an agent go from a folder of material and two sentences of intent to a finished, editable layout in four or five tool calls, while the person watches it appear in the FormDesign window. The premise is division of labour: FormDesign does the deterministic work cheaply (reading files, choosing and filling a template, threading text, fitting copy, finding problems), and the agent spends its tokens only on judgement (what the person meant, what to fix, what to tell them).

The failure this skill prevents is the expensive one: reading every source file into context, then laying out frame by frame with low-level commands. That costs tens of thousands of tokens and produces worse pages than a template. Intake and make_layout replace both steps.

## Routing

Start with `sub-skills/layout-director/SUB-SKILL.md` for any request to make or change a layout; it runs the loop and pulls in the specialists. Load a specialist directly only for a narrow question.

| The request is about | Load |
| --- | --- |
| Making anything from files and a brief, end to end | `layout-director` |
| What to pass to intake, writing the brief, fields like CTA or date, captions and image roles | `intake-curator` |
| Which template, the 71 built-ins, sizes, kinds, why the ranking chose one | `template-picker` |
| Reading the Make report, fixing kept sample text, swapping images, moving or restyling frames, adding pages | `layout-finisher` |
| Brand colours and fonts, brand kits, re-skinning | `brand-stylist` |
| Shapes, paths and vector art: corners, offset path, outline stroke, Pathfinder, simplify, Shape Builder, blends, width profiles, effects and warps, brushes, Repeat, symbols, recolour, Image Trace, Live Paint, masks, meshes, envelopes, artboards | `path-artist` |
| Saving, exporting (PDF, IDML, a website, HTML, EPUB, PNG, JPG), publishing online, packaging | `publisher` |
| Reading, searching or extracting a PDF | `pdf-reader` |
| No MCP connection: the command line | `cli-fallback` |
| Designing a brand new template | the sibling skill `formdesign-template-creator` |

Paths inside a SUB-SKILL.md resolve against that specialist's folder; `references/` at this level are shared.

## The loop in one breath

1. `intake` with every absolute path and the brief in the person's words.
2. `make_layout` with the pack id (and a template id when the person named a kind the ranking missed).
3. `preview` page 1, and any page the report mentions.
4. `set_slots` for what the report lists as kept or emptied; `run_commands` only for changes slots cannot express.
5. `save_document` and `export_document` as asked (`format: "web"` for a website or blog, `publish_website` for a link to look at now); tell the person what is still sample or placeholder.

## Gates before saying it is done

- The last `make_layout` or `set_slots` report has no `kept` slot that should hold the person's content, or each one is named to the person as still sample text.
- At least one `preview` was looked at after the last change.
- `preflight` reports no errors, or each remaining one is explained (overset in a story that will grow, a low-resolution image the person supplied).
- Exported files exist at the paths reported by `export_document`.

## Reference files

- `references/tools.md`: every MCP tool with its parameters, generated from the engine by `./formdesign agents sync`.
- `references/templates.md`: the 71 built-in templates with sizes, pages, kinds, flows and slots, generated by the same command.
- `references/slots.md`: slot names, what the Make pass fills them with, and how set_slots treats text, images and flows.
- `references/brief.md`: how a brief is parsed into kinds, tone, colours, size, pages and fields.
- `EVALS.json`: the evaluations and trigger set this skill was checked against.
